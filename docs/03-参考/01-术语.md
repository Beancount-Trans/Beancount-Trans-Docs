## 术语

| 术语 | 定义 |
| :--- | :--- |
| 账本 | 以 Beancount 文本（`.bean`）承载的复式记账数据集合；平台写入用户 `Assets` 目录下主文件与子文件。（同义：Ledger） |
| 自有账本 | 用户账号下由平台托管与写入的账本，默认形态；启用 Git 同步后以自管仓库为准的形态称「本地账本」。 |
| 条目 | 账本中的一条 Beancount 指令（`transaction`、`balance`、`pad`、`open`、`close` 等），或待审核队列中的一条待写入数据；计量用「条」，「记录」只作动词。 |
| 解析 | 将上传的原始账单转为账本可消费的条目的过程。 |
| 映射 | 把账单里的文字（交易对方、商品说明）匹配到目标账户的规则；口语说的「支出分类」由「账户 + 关键字映射」共同实现，规则与配置界面统一写「映射」与「账户」。 |
| 账户 | Beancount 账户路径（如 `Expenses:Food`），表示资金分类；与登录身份「账号」区分。 |
| 账号 | 平台登录身份或第三方账号（如 GitHub 账号）；不指 Beancount 账户。 |
| 标签 | Beancount 行内的标记（如 `#Project/A`），用于跨账户的临时归类或项目管理；与账户的分工见 [账户 vs 标签](https://trans.dhr2333.cn/docs/%E8%A7%A3%E9%87%8A/account-vs-tag)。 |
| 待办 | 统一队列中的一个事项：对账、条目审核或循环待办；不写「任务」「提醒」。后台异步作业称「解析任务」。 |
| 审核 | 写入账本前的人工确认环节；功能名统一「条目审核」，点击写入的动作写「确认写入」。 |
| 循环待办 | 按周期重复生成待办的规则；不写「周期提醒」「周期任务」。 |
| Fava | 平台内置的 Beancount 报表界面，入口写「打开 Fava」；首次提及可写「Fava 专业报表」。 |
| 共享账本 | 他人以只读方式分享给你并绑定到你账号下的账本；「分享」指授权这一动作本身。 |
| 访问令牌 | 形如 `bct_…` 的只读凭证，供 MCP 客户端等外部程序访问账本；见 [接入 AI 客户端](https://trans.dhr2333.cn/docs/%E6%93%8D%E4%BD%9C%E6%8C%87%E5%8D%97/connect-ai-client)。 |
| Copilot | 平台内置的 AI 账本助手：用自然语言问账、复盘，并把一句话记成待审核条目；只读查询，不直接改账。首次出现写「Copilot（账本助手）」，后文统一写「Copilot」，不单写「助手」。 |
| 自托管 | 用 Docker Compose 把整套平台部署在你自己的服务器上；见 [自托管](https://trans.dhr2333.cn/docs/developer/self-host)。 |
| 对账 | 核对资产账户的账面余额与实际余额，把差额写入账本；按「对账周期」生成待办。 |
| 撤销对账 | 作废最近一次已完成对账并重做；按钮与提示统一写「撤销上次对账」，不写「撤回」。 |
| 账户核对 | Git 用户账本账户与平台账户的路径比对：补齐缺失账户、为改名账户配对；不涉及余额。把平台账户变更写入账本的操作称「账户同步」，两者不是同一件事。 |
| 交易对方 | 账单中的收付款方；不写「对手方」「商户」。 |
| 商品说明 | 账单中的商品或用途描述；不写「商品」「商品/币种」。 |
| 收支方向 | 收入 / 支出 / 不计收支；不写「收支类型」「交易类型」。账单原始字段「交易分类」不在此列。 |
| 支付方式 | 账单中的付款渠道；不写「付款方式」。 |
| 本地账本 | 启用 Git 同步后以自管仓库为准的账本形态，入口在「个人设置 → 高级：本地账本」；普通用户无需启用。与「自有账本」相对。 |

## 写法约定

- 「记录」只作动词（记录一笔、记录日志）；指代单条数据时写「条目」。
- 「待办」不写「任务」；后台异步作业写「解析任务」。
- 「审核」指写入前的确认环节；点击写入的动作写「确认写入」。
- 「撤销」不写「撤回」；按钮与提示统一「撤销上次对账」。
- 「交易对方」「商品说明」「收支方向」是账单字段的标准称呼，不写「对手方」「商品」「收支类型」。
- 「账号」指登录身份，「账户」指 Beancount 账户；两者不混用。
- 「分类」只作面向用户的简称；规则与配置界面写「映射」「账户」。
- 「草稿」指未提交的本地编辑，保留现用词；「暂存区」仅指 Copilot 记账的服务端中转区。

部分术语的展开说明见：[核心概念](https://trans.dhr2333.cn/docs/%E5%BD%92%E6%A1%A3/core-concepts)。

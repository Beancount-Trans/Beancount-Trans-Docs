不同来源的条目确认后，写入的账本文件与方式不同：

| 来源             | 确认后写入                       | 写入方式        |
| :------------- | :-------------------------- | :---------- |
| Copilot / 解析首页 | `trans/collect.bean`        | 追加          |
| 对账             | `trans/reconciliation.bean` | 追加（由对账流程维护） |
| 账单文件解析         | `trans/{账单名}.bean`          | 覆盖          |
| 账户同步           | `trans/collect.bean`        | 覆盖/追加       |

![](https://daihaorui.oss-cn-hangzhou.aliyuncs.com/djangoblog/20261017153753932.png)

## 通用规则

- 条目确认前先进入**暂存区与统一审核队列**，审核截止时间为 **24 小时**。
- 到期仍未处理：系统每小时检查一次，到期的待办会**自动写入**。
- 写入前都会做 Beancount 语法校验；校验不通过则整体不写入。

## 账户同步

账户的新建、启用、关闭、删除与币种变更也会写入账本：

- **新建**：写 `open` 与一条 `note "平台创建账户"`。`open` 日期统一为 `2000-01-01`（早于任何交易，避免回溯上传旧账单时报错）。
- **启用 / 关闭**：追加带日期的 `note "平台启用账户"` 或 `note "平台关闭账户"`。
- **删除**：追加 `close`。
- **币种**：修改后重写已有 `open` 的币种列表，保留开户日期、booking 与行尾注释。

> Git 用户在 **「Git 同步 → 提交到账本」** 后，`trans/` 中的条目会按交易日期归入仓库根 `{年}/{月}.bean` 并进入 Git 历史。

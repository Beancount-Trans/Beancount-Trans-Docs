**让平台账户和 Git 账本保持一致**：账本决定账户有没有，平台只补充怎么用。

## 适用场景与前提

- 已按 [配置 Git 同步](https://trans.dhr2333.cn/docs/%E6%93%8D%E4%BD%9C%E6%8C%87%E5%8D%97/git-sync) 接好仓库；

## 先记住三条

1. **账本为准**：账户是否存在、路径、币种，都以账本里的 `open` 为准。
2. **平台日常只写 `trans/`**：不改 `main.bean`、`account/**`、`{年}/**`；只有您点「提交到账本」时才会写入 `{年}/` 并推送。
3. **看 `open` 在哪**：只在平台区时平台可以改；进了账本就只能在账本改。

## 平台区托管 vs 账本托管

| 状态    | 判断依据                                    | 平台可以做什么                  |
| :---- | :-------------------------------------- | :----------------------- |
| 平台区托管 | 账户的 `open` 只在 `trans/`，账本里没有 `open` 或引用 | 改名、改币种、删除，改动只落在 `trans/` |
| 账本托管  | 账本里已有该账户的 `open`（或仍有引用）                 | 只能改平台属性；改名、改币种、删除需回到账本   |

> 转成账本托管有两条路：在账本补 `open`，同步时会删掉 `trans/` 里的重复 `open`；或点「提交到账本」，平台新建账户的 `open`（`2000-01-01`）会进入 `2000/01.bean`。

## 把已有账本的账户带到平台

1. **自动**：**「自动导入账本新增账户」** 默认开启；打开 **「个人设置 → Git 同步」** 点 **「立即同步」** 即可。若曾关闭，可在 **「高级设置」** 重新打开。
2. **手动**：打开 **「解析配置 → 账本账户」**，点 **「账户核对」**，按「账本有、平台无」逐个补。

> 只补账本里显式写了 `open`、路径合法的账户；只新增，不改账本。

## 日常操作

平台区托管直接在平台改；账本托管先改账本，推送并同步，改名再用 **「账户核对」** 配对。

| 想做的事    | 平台区托管                    | 账本托管                      |
| :------ | :----------------------- | :------------------------ |
| 新增账户    | **「新增账户」** → **「提交到账本」** | 账本加 `open` → 推送 → 同步      |
| 改名      | 直接在平台改                   | 账本改名 → 推送 → 同步 → 核对配对     |
| 启用 / 关闭 | 平台开关                     | 平台开关（仅平台状态，不等于账本 `close`） |
| 改币种     | 平台改                      | 改账本 `open`                |
| 删除账户    | 平台删                      | 先在账本处理，再清平台               |

> 平台新建的 `open` 在 **「提交到账本」** 后进入 `2000/01.bean`，账户转为账本托管；账本已 `close` 的账户不会再被补齐；模板只用 **「合并」**。

## 账户核对怎么用

- **「平台有、账本无」**：账本里可能改名或删了。选中新账户 → 点 **「应用配对」**，平台跟着改，映射自动跟随。
- **「账本有、平台无」**：平台还缺的账户。可手动新增，或开自动补齐后同步。
- 配对只改平台，不改账本，也不提交 Git。
